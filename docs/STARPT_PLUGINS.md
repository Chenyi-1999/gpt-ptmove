# STARPT 插件

## 安装、更新和移除

把发行附件中的 `downloader-summary.zip` 放到 STARPT 容器的 `/app/data/plugins/`，再在「插件」页面点击「刷新插件」。宿主机目录由 Compose 的数据挂载决定；腾讯 152 用 `/opt/gpt-ptmove-nexus/data/plugins/`。首次刷新后示例立即可用。

下载器统计 2.0 需要支持 `downloader.inventory` 的 STARPT。打开「插件 → 下载器统计」，选择下载器及分类、标签、站点或保存路径。列表默认折叠，按状态筛选时显示匹配的数量，展开某组才加载该组的种子名单。一个任务有多个标签时会分别计入各标签，顶部总数仍按任务计算。

统计在首次查看和主动刷新时读取选中的下载器，界面不轮询。切换维度及展开列表复用短时快照。qBittorrent 按实际分类和标签统计，Transmission 的 labels 作为标签。站点优先匹配 STARPT 站点配置，未匹配的 tracker 按主机名归类。下载器读失败会提示错误，不会按空清单计数。

替换同名 ZIP 再刷新即可更新，校验失败时会显示原因并保留上一版。删除文件并刷新即可移除入口，配置独立保留。STARPT 服务启动时从已保存的缓存恢复，目录只在 Web 手动刷新时读取。刷新时如果发现缓存的 WASM 缺失或损坏，会从现有 ZIP 重新校验并重建。运行期间丢失的状态文件也会在刷新时恢复，保留此时的启停和设置。首次升级时已有旧 JSON 文件也可通过一次手动刷新恢复。

## 编写可执行插件

以 [下载器统计示例](../examples/plugins/downloader-summary/) 为起点。用 Go 1.23 或更新版本构建，打包机需有 Python 3。在仓库根目录执行：

```sh
python3 examples/plugins/pack.py examples/plugins/downloader-summary --output-dir ./plugin-build
```

ZIP 文件名须与插件 ID 相同。包根目录包含 `plugin.json` 和 `plugin.wasm`。清单用 `schema_version: 2`，声明 ID、名称、版本、`fields`、`actions` 及所需能力。ID、字段键和动作 ID 用小写字母、数字与连字符。字段类型支持 `string`、`boolean`、`integer`，字符串可以列出可选值。

模块使用 WASI Preview 1，通过标准输入收到一个 JSON 对象，包含 `action`、`settings` 和 `resources`。标准输出返回 `message` 和 `blocks`，内容可以是文字、统计数值和表格。代码可用其他支持 WASI 的语言编写。STARPT 每次执行动作才启动模块，限制内存、输出和运行时间，按能力提供所需数据。

v1.1.0 的外部插件能力是 `downloader.summary`，返回配置中的下载器名称、启用状态和 STARPT 已记录的累计流量。插件通过工作台运行按钮或单独设置的定时计划执行。计划默认关闭，设定间隔后按到期时间唤醒。支持停用插件、查询最近定时运行状态和重新启用。

## 自动转种

在「插件 → 自动转种」管理自动规则、候选预览和执行记录。在「设置 → 转种」管理匿名发布、PTGen、默认下载器、发种参数和下载器标签。旧的 `/settings/automation` 地址也可打开转种设置。插件开关与每月计划独立。关闭插件暂停新的写操作并保留未完成任务，已提交到站点的结果仍可核对。自动转种继续由内置后端执行源站限制、目标查重与配额检查。

## 旧版 JSON 清单

旧版文字、链接和统计卡片仍可使用。文件放入同一目录，点击「刷新插件」读取。可执行插件与 JSON 同 ID 时显示可执行插件，并在刷新结果中提示冲突。内置插件 ID 保留。

例如保存为 `ops.json`：

```json
{
  "schema_version": 1,
  "id": "ops",
  "name": "转种工作台",
  "version": "1.0",
  "description": "集中查看待整理的资料和发布记录。",
  "blocks": [
    {"kind": "metric", "title": "转种资料数", "metric": "transfer_drafts"},
    {"kind": "link", "title": "打开任务记录", "target": "/publish-logs"},
    {"kind": "text", "title": "检查源站要求", "text": "发种前核对资料和来源：禁止转载的种子不能转发。"}
  ]
}
```

- `id` 与文件名相同，使用小写字母、数字和连字符。
- `text` 展示普通文本。`link` 打开应用内已有的功能，例如 `/seed-maintenance`、`/publish-logs`、`/settings/transfer`、`/settings/site-profiles`、`/settings/api`。
- `metric` 支持 `visible_torrents`、`transfer_drafts`、`configured_sites`。
- 清单支持最多 16 个内容块，每个文件最多 64 KiB。错误文件会在插件页面标明。目录读取失败时，已加载的插件继续可用。

插件面板基于声明文件运行。需要新增数据读写或后台动作时，通过 STARPT 的服务代码增加可供插件调用的功能，发布仍受源站规则检查。

## 北洋园刷流

从 v1.1.7 起，将发行附件 `tjupt-rss.zip` 放到数据目录的 `plugins/`，在「插件」点击「刷新插件」，再打开「北洋园刷流」。首次从内置版升级时，已有配置和任务台账可以直接沿用。安装后通过「正式启动」恢复 RSS 循环。

WASM 包声明预览、H&R 查询、试运行、启动和停止五个动作，并确认管理员本次选中的动作。STARPT 执行对应的宿主接口，处理订阅地址、站点 Token、qB 和任务台账。RSS 循环由宿主按已有规则运行，停用或移除包将暂停循环。再次启用或重装后，由管理员手动启动。

在顶部配置区填写站内生成的 RSS 地址、北洋园 API Token、已配置的 qB 下载器、运行间隔、种子标签和分类。点击「保存」保存同一区域内的所有字段，运行状态保持原样。留空已保存的凭据输入框会保留原值。

1. 「试运行一次」按保存的条件向 qB 添加至多一条符合条件的暂停任务。可以在 qB 中核对标签、分类和目录。
2. 「正式启动」立即读取 RSS，随后按设定间隔继续获取。默认每 1 分钟一次。新加入的任务正常开始下载。插件也会启动同一份配置下由它暂停添加、且身份和状态仍核对一致的试运行任务。
3. 「停止循环」停止继续读取和添加。停止前已提交给 qB 的任务由 qB 继续管理。

预览使用已保存的 RSS 地址，展示体积和 H&R 基础时长。H&R 查询使用同一个配置区保存的 Token 和下载器，兼容「北洋园」和旧标签，显示站点提供的剩余做种时间。

正式投种和试运行使用同一个「北洋园」标签。新的投种请求短暂附带唯一回执标签，台账确认下载器、哈希和加入时间后才移除回执标签。原有任务会在运行时逐步转换，尚未确认的单任务标记保留。用户自己设置的其他标签不会被转换。手动给种子加上「北洋园」标签可以查看 H&R；自动清理还要求有匹配的投种台账。

已转换的任务由新版台账识别。若降级到仍依赖单任务标记的版本，应先停用 RSS 循环；只有用台账核对 qB 的哈希和加入时间并恢复对应旧标签后，旧版才能继续恢复或清理这些任务。

在管任务数上限填 `0` 表示不限数量，也可以设置任意正整数。插件仍按单种体积、已管理总容量和重复记录筛选。曾保存的任务上限会在升级后继续生效。H&R 查询会分批处理超过 50 个任务的列表。

在北洋园插件中可直接开启「使用站点上传限速」。开启后，试运行和正式循环新加入 qB 的任务使用「设置 → 站点管理 → 北洋园」的上传限速。页面显示站点当前值，站点设置为不限速时按 qB 自身规则处理。开关默认关闭，操作后自动保存。已添加的任务继续使用它们加入时的限速。

### 达标后低速移除

在同一配置区启用「HR 达标后按低速条件自动清理任务」，保存与 RSS 同账号的北洋园 API Token、上传阈值与连续低速时长。功能默认关闭，阈值默认 100 KiB/s，低速时长默认 60 分钟。只有正式循环中的插件自管、已完成且正在做种的任务才进入判断。

1. 站点明确返回已达标或后达标后，记录第一次确认。正式循环约每分钟采样一次 qB，低于阈值时积累低速时间。达到阈值、采样中断或结果异常时重新观察。RSS 继续按用户设置的间隔获取。
2. 连续低速达到设定时长，并距首次达标确认至少 15 分钟后，移除前再查同一条 H&R 记录和 qB 的当前上传状态。北洋园查询结果缓存 10 分钟。[北洋园 H&R API 文档](https://github.com/tjupt/autoremove-torrents/blob/master/hnr_api.md#注意事项)
3. 两次都达标、任务归属仍吻合、上传仍低于阈值时移除 qB 任务并保留下载文件。移除结果不明时先核对任务是否仍存在，确认从 qB 消失后才释放插件的任务和体积额度。

界面显示站点的实际 H&R 剩余时长；试运行仅暂停添加新任务。

### 旧版签名接口

早期版本的退种及清理接口为已安装配套飞牛 Agent 的实例保留。旧版运行模式与当前 RSS 循环互斥。下列环境配置只适用于已运行的旧版签名集成。

| 环境变量前缀 | STARPT | 飞牛 Agent |
| --- | --- | --- |
| `PTMOVE_TJUPT_RETIRE_KEY` | 独立生成的随机签名密钥，至少 32 个字符 | 同一密钥 |
| `PTMOVE_TJUPT_HNR_TOKEN` | 管理账号的北洋园 API Token | 无需配置 |
| `PTMOVE_TJUPT_TRACKER_PASSKEY` | 与该 Token 同一账号的 Tracker passkey | 无需配置 |

飞牛 Agent 使用 `PTMOVE_TJUPT_RETIRE_KEY_FILE` 读取其已挂载的 `/run/ptmove/agent/` 目录中的私有文件。暂停请求必须使用已配置的账号 Token，飞牛会核对每个 Tracker URL 的 `passkey` 参数。密钥和账号不匹配时保留任务。旧版通道可继续查询 qB。通用暂停、删除接口保持关闭。

#### 旧版自动投种与清理

旧版接口提供单种体积范围、总在管体积和任务数。默认单种 0–10 GiB、总量 50 GiB、最多 3 项。插件从 RSS 的 enclosure 读取站内 `.torrent`，以其实际载荷总大小计算规则和原子预留。下载中、做种中、待删除和结果未确认的任务占用容量。调低上限或容量用完时停止新增，已有任务继续保种。

| 种子体积 | 基础累计做种时间 |
| --- | ---: |
| ≤10 GiB | 24 小时 |
| >10–20 GiB | 48 小时 |
| >20–30 GiB | 72 小时 |
| >30–40 GiB | 96 小时 |
| >40–50 GiB | 120 小时 |
| >50 GiB | 168 小时 |

在基础时长上叠加可调缓冲，默认 6 小时。达到本地做种门槛且北洋园确认达标或免考后，开始按单种上传速度采样，默认低于 100 KiB/s 连续观察 60 分钟、每 5 分钟检查。速度达到阈值、状态无法确认或检查中断时重新观察。

首次满足条件的巡检只打 `starpt-tjupt-pending-delete` 标签。默认清理模式为「标记并保留」。管理员单独启用实际删除后，后续检查重新验证时间、上传速度、H&R、账号、任务和数据文件归属，通过后才删除该 qB 任务及其私有目录中的数据。重复、共享、符号链接、目录无法证明归属或回执不明确时保留额度。结果待核实的删除在本机仍能确认同一任务且旧请求过期后，重新开始观察。

STARPT 需要在私有文件中提供同一账号的 RSS，通过 `PTMOVE_TJUPT_RSS_URL_FILE` 指向该文件。STARPT 和飞牛都需要设置相同的 `PTMOVE_TJUPT_AUTO_ROOT`，它是专用于此插件的绝对目录。qB 须可写，配套飞牛 Agent 以同路径只读检查。投种、标签和清理需要已安装的配套 Hub、Agent 和前面的独立签名配置。首次部署时调度保持关闭。

实际文件删除需要专用的飞牛 qB 实例与存储目录，所有写入由这个 Agent 管理，不与其他应用或下载任务共用。确认隔离后，在 STARPT 和 Agent 都设置 `PTMOVE_TJUPT_AUTO_EXCLUSIVE_QB=1`。删除请求前后检查任务归属、目录和回执。在 qB 里发现非插件任务时，继续保留文件。若已领单的写入超时，设置锁定至原租约和签名失效。

恢复备份后，如果 qB 仍有带自动管理标签的种子，但台账中已无对应记录，插件会暂停自动投种和清理，避免把未计入体积的任务忽略掉。
